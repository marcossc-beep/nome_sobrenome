// ### Passo 1: como o front conversa com a API

O front (páginas HTML) roda no navegador. A API (server.js) roda no Node, na porta 6767.
Para conversar, o front usa o fetch, o mesmo que você usou no cadastrar() e no buscar() da pokedex:

    const resposta = await fetch('http://localhost:6767/login', {
        method: 'POST',                                   // GET, POST, PUT ou DELETE
        body: JSON.stringify({ email, senha }),           // o que vai para a API
        headers: { 'Content-Type': 'application/json' }   // avisa que o corpo é JSON
    })
    const dados = await resposta.json()                   // lê a resposta da API

- resposta.ok é true quando o status é 200 a 299. Em 400 e 401 é false.
- await só funciona dentro de uma função async.
- GET e DELETE não têm body.


// ### Passo 2: liberar o CORS na API

Como o front e a API são "endereços" diferentes, o navegador bloqueia a conversa por segurança.
Esse bloqueio se chama CORS. Para liberar, a API diz ao navegador que aceita as chamadas.
No server.js, logo abaixo do const servidor = Fastify(), registre o cors:

// >>> server.js
servidor.register(cors, {
    origin: '*',
    methods: ['GET', 'POST', 'PUT', 'DELETE']
})
// <<<

// ATENÇÃO: o @fastify/cors libera por padrão só GET, HEAD e POST.
// Se você esquecer de listar PUT e DELETE em methods, o editar e o excluir falham no navegador
// (mas funcionam no REST Client, o que confunde). Liste todos os métodos que usa.
//
// Sintoma do CORS faltando: no console do navegador (F12) aparece "blocked by CORS policy"
// ou "Failed to fetch". Depois de salvar o server.js a API reinicia sozinha (npm start usa --watch).

// ### Passo 4: scripts.js (as funções que todas as páginas usam)

Como vamos ter várias páginas, as funções de sessão ficam num arquivo só e cada página inclui com
<script src="scripts.js"></script>. Assim você escreve uma vez e usa em todas.

Antes, o que é o localStorage: uma "gaveta" do navegador que guarda texto mesmo se você recarregar a página.
- localStorage.setItem('chave', valor)    guarda
- localStorage.getItem('chave')           lê (ou null se não existe)
- localStorage.removeItem('chave')        apaga
- JSON.stringify(objeto) e JSON.parse(texto) transformam objeto em texto e texto em objeto
  (o localStorage só guarda texto).

Depois do login guardamos 3 coisas: token, expira (quando vence) e usuario (com o nome).

Crie o arquivo FRONT/scripts.js:

// >>> FRONT/scripts.js
const API = 'http://localhost:6767'

// Usuário logado salvo no navegador (ou null)
function pegarUsuario() {
    return JSON.parse(localStorage.getItem('usuario'))
}

// A sessão é válida se existe token e o horário de expiração ainda não passou
function sessaoValida() {
    const token = localStorage.getItem('token')
    const expira = Number(localStorage.getItem('expira'))
    return token && Date.now() < expira
}

// Sai do sistema: apaga tudo e volta para o login
function sair(mensagem) {
    localStorage.removeItem('token')
    localStorage.removeItem('usuario')
    localStorage.removeItem('expira')
    if (mensagem) alert(mensagem)
    window.location.href = 'index.html'
}

// Colocar no topo de toda página que precisa de login
function protegerPagina() {
    if (!sessaoValida()) {
        sair('Sessão expirada. Faça login novamente.')
    }
}

// fetch já com o token. Se a API responder 401 a sessão acabou.
async function api(caminho, metodo = 'GET', corpo) {
    const opcoes = {
        method: metodo,
        headers: { Authorization: 'Bearer ' + localStorage.getItem('token') }
    }

    if (corpo) {
        opcoes.headers['Content-Type'] = 'application/json'
        opcoes.body = JSON.stringify(corpo)
    }

    const resposta = await fetch(API + caminho, opcoes)
    const dados = await resposta.json()

    if (resposta.status === 401) {
        sair(dados.message)
    }

    return dados
}

// Mostra a data do banco no formato brasileiro
function formatarData(data) {
    return new Date(data).toLocaleString('pt-BR', { dateStyle: 'short', timeStyle: 'short' })
}
// <<<

// O que cada função faz:
//   sessaoValida()   -> critério 3.2: a sessão acaba quando o horário "expira" passa
//   sair()           -> critério 4.2: apaga os dados da sessão e volta ao login
//   protegerPagina() -> impede abrir as telas sem estar logado
//   api()            -> é o fetch que você já conhece, só que já manda o token no header Authorization
//                       (as rotas protegidas da API exigem) e, se a API responder 401 (token vencido), faz sair()
//   formatarData()   -> mostra a data em português (usada na tela de agendamentos)

// >>> FRONT/index.html
    <script src="scripts.js"></script>
    <script>
        // Se já estiver logado e a sessão não expirou, vai direto para a principal
        if (sessaoValida()) {
            window.location.href = 'principal.html'
        }

        async function entrar() {
            const email = document.getElementById('email').value
            const senha = document.getElementById('senha').value
            const mensagem = document.getElementById('mensagem')

            // Validação no front: campos vazios
            if (!email || !senha) {
                mensagem.textContent = 'Preencha e-mail e senha!'
                return
            }

            const resposta = await fetch(`${API}/login`, {
                method: 'POST',
                body: JSON.stringify({ email, senha }),
                headers: {
                    'Content-Type': 'application/json'
                }
            })
            const dados = await resposta.json()

            // Validação vinda do back: usuário ou senha inválidos
            if (!resposta.ok) {
                mensagem.textContent = dados.message
                return
            }

            localStorage.setItem('token', dados.token)
            localStorage.setItem('expira', dados.expira)
            localStorage.setItem('usuario', JSON.stringify(dados.usuario))

            window.location.href = 'principal.html'
        }
    </script>
</body>
</html>
// <<<

// Pontos para entender:
// - O login não usa a função api(), porque ainda não existe token. Ele usa o fetch direto.
// - ${API} vem do scripts.js, que foi carregado na linha de cima.
// - window.location.href = 'principal.html' é o que "redireciona" (critério 3.1).
// - Teste: campos vazios, senha errada (a mensagem da API aparece em vermelho) e senha certa.
//   No F12 > Application > Local Storage você vê token, expira e usuario guardados.
// - A principal.html ainda não existe: depois do login certo a página some. Siga para o passo 6.

// ### Erros comuns

- A tela de login não faz nada: abra o F12 > Console. Provavelmente tem um erro de JavaScript ou o scripts.js não carregou
  (confira o nome do arquivo no <script src="scripts.js">).
- "Failed to fetch": a API não está rodando, a porta está errada no scripts.js (const API) ou faltou o CORS.
- A mensagem de erro não aparece: o <p id="mensagem"> precisa existir no HTML com esse mesmo id.
- Voltou para o login logo depois de entrar: o localStorage não guardou o expira (confira a resposta do /login no Network).
- "Cannot read properties of null (reading 'nome')": pegarUsuario() devolveu null, ou seja, não há usuário salvo.
  Chame protegerPagina() ANTES de usar pegarUsuario().
- Enter não envia o login: de propósito, o envio é pelo botão entrar (onclick), como na pokedex.
