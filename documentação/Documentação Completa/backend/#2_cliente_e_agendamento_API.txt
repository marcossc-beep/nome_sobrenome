// ### CLIENTE: a ideia

O caderno diz: "Ao cadastrar um novo cliente, o usuário deve associá-lo a um barbeiro."
No banco isso é a chave estrangeira cliente.barbeiro_id (NOT NULL: todo cliente tem barbeiro).
O front manda o barbeiro_id no corpo do POST e a API confere se esse barbeiro existe antes de gravar.


// ### CLIENTE: rota POST /clientes

A listagem GET /clientes (com JOIN, para trazer o nome do barbeiro) está em #1_busca_e_JOIN.txt.
Cole no server.js, junto das outras rotas:

// >>> server.js
servidor.post('/clientes', { preHandler: autenticar }, async (request, reply) => {
    const body = request.body

    if (!body || !body.nome || !body.barbeiro_id) {
        return reply.status(400).send({ message: 'Nome e barbeiro são obrigatórios!' })
    }

    const barbeiro = await sql.query('SELECT id FROM barbeiro WHERE id = $1', [body.barbeiro_id])
    if (barbeiro.rows.length === 0) {
        return reply.status(400).send({ message: 'Barbeiro informado não existe!' })
    }

    await sql.query(
        'INSERT INTO cliente (nome, telefone, estilo_corte, barbeiro_id) VALUES ($1, $2, $3, $4)',
        [body.nome, body.telefone, body.estilo_corte, body.barbeiro_id]
    )

    return reply.status(201).send({ message: 'Cliente cadastrado!' })
})
// <<<

// A conferência (SELECT id FROM barbeiro...) devolve uma mensagem clara. Sem ela, um barbeiro_id inexistente
// estoura um erro de chave estrangeira do Postgres e a API responde 500.
// (Se ainda não fez a função autenticar, tire o { preHandler: autenticar } por enquanto.)

// ### AGENDAMENTO: como a data é guardada e enviada

- No banco a coluna é TIMESTAMP (data e hora juntas): 2026-11-18 14:30:00.
- Front e API trocam datas no formato ISO: 2026-11-18T14:30 (o T separa a data da hora).
- O Postgres aceita esse formato direto. Não precisa converter.


// ### AGENDAMENTO: rotas POST e PUT

O GET /agendamentos (JOIN triplo e ORDER BY data_agendamento) é o critério 7.1.
Ele está explicado em #1_busca_e_JOIN.txt. Aqui ficam as duas rotas que faltam.

O POST existe para você conseguir criar agendamentos de teste pela tela:

// >>> server.js
servidor.post('/agendamentos', { preHandler: autenticar }, async (request, reply) => {
    const body = request.body

    if (!body || !body.data_agendamento || !body.servico || !body.barbeiro_id || !body.cliente_id) {
        return reply.status(400).send({ message: 'Data, serviço, barbeiro e cliente são obrigatórios!' })
    }

    await sql.query(
        'INSERT INTO agendamento (data_agendamento, servico, barbeiro_id, cliente_id) VALUES ($1, $2, $3, $4)',
        [body.data_agendamento, body.servico, body.barbeiro_id, body.cliente_id]
    )

    return reply.status(201).send({ message: 'Agendamento cadastrado!' })
})
// <<<

O PUT recebe SÓ a data nova e muda só essa coluna (critério 7.2):

// >>> server.js
// Atualiza SÓ a data do agendamento
servidor.put('/agendamentos/:id', { preHandler: autenticar }, async (request, reply) => {
    const body = request.body
    const id = request.params.id

    if (!body || !body.data_agendamento) {
        return reply.status(400).send({ message: 'A nova data é obrigatória!' })
    }

    const resultado = await sql.query(
        'UPDATE agendamento SET data_agendamento = $1 WHERE id = $2',
        [body.data_agendamento, id]
    )

    if (resultado.rowCount === 0) {
        return reply.status(404).send({ message: 'Agendamento não existe!' })
    }

    return reply.status(200).send({ message: 'Data do agendamento atualizada!' })
})
// <<<

// resultado.rowCount diz quantas linhas o UPDATE alterou. Se foi zero, o id não existe (404).
// Sempre use WHERE no UPDATE. Sem o WHERE, TODAS as linhas da tabela mudam de data.
// (Se ainda não fez a função autenticar, tire o { preHandler: autenticar } por enquanto.)

// ### Erros comuns

- "Barbeiro informado não existe!" (400): o barbeiro_id enviado não está na tabela barbeiro. Confira com SELECT * FROM barbeiro.
- "violates foreign key constraint" (500): faltou a conferência antes do INSERT, ou o cliente_id/barbeiro_id não existe.
- 401 em tudo: faltou o header Authorization: Bearer <token> no .http, ou o token venceu. Faça login de novo.
- Atualizou a data e TODOS os agendamentos mudaram: faltou o WHERE no UPDATE.
- "Agendamento não existe!" (404): o id que está na URL do PUT não existe.
- A data mudou de horário (algumas horas a mais ou a menos): o JavaScript converteu o fuso. Envie a data como veio do input
  (2026-11-17T08:30) e deixe o Postgres guardar como TIMESTAMP, sem timezone.
