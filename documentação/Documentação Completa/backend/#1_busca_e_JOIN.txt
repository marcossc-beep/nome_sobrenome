// ### Busca por termo

A busca tem 3 pedaços que se encaixam:
1. No SQL: filtrar com ILIKE e % (qualquer texto antes ou depois).
2. Na API: receber o termo pela URL (?busca=termo) com request.query.
3. Na tela: um formulário em que o usuário digita o termo, confirma e a lista atualiza.

// SQL (teste no pgAdmin antes de programar)

SELECT id, nome FROM barbeiro
WHERE nome ILIKE '%ana%'
ORDER BY id;

- ILIKE ignora maiúsculas e minúsculas (LIKE comum diferencia).
- O % vale por "qualquer coisa": '%ana%' acha "Ana Souza", "Mariana", "Juliana"...
- A busca precisa de no mínimo UM termo/campo (critério 5.2): aqui é o nome.
- Nunca monte o SQL juntando texto com +. Use $1 (evita SQL injection).

// API: o termo vem na URL
//
// Tudo que vem depois do ? na URL chega em request.query:
//     GET http://localhost:6767/barbeiros?busca=ana        ->  request.query.busca === 'ana'
// Se não vier busca (GET /barbeiros), request.query.busca é undefined e listamos todos.

servidor.get('/barbeiros', { preHandler: autenticar }, async (request, reply) => {
    const busca = request.query.busca

    if (busca) {
        const barbeiros = await sql.query(
            'SELECT id, nome FROM barbeiro WHERE nome ILIKE $1 ORDER BY id',
            [`%${busca}%`]
        )
        return reply.send(barbeiros.rows)
    }

    const barbeiros = await sql.query('SELECT id, nome FROM barbeiro ORDER BY id')
    reply.send(barbeiros.rows)
})

// O valor do $1 é `%${busca}%`: o termo digitado com um % de cada lado.
// O SELECT lista as colunas uma a uma (só id e nome): o cpf e a senha, que estão em hash, nunca saem da API.

// ### JOIN (juntar tabelas)

Por que precisamos: cliente guarda só o barbeiro_id (um número). Para mostrar o NOME do barbeiro
precisamos juntar as duas tabelas pela chave estrangeira.

// JOIN simples: cliente + barbeiro

SELECT cliente.*, barbeiro.nome AS barbeiro_nome
FROM cliente
INNER JOIN barbeiro ON cliente.barbeiro_id = barbeiro.id
ORDER BY cliente.id;

- INNER JOIN tabela ON chave_estrangeira = chave_primaria.
- AS dá um apelido à coluna. Sem o AS, o resultado teria duas colunas "nome" e uma sobrescreveria a outra no JSON.

servidor.get('/clientes', { preHandler: autenticar }, async (request, reply) => {
    const clientes = await sql.query(`
        SELECT cliente.*, barbeiro.nome AS barbeiro_nome
        FROM cliente
        INNER JOIN barbeiro ON cliente.barbeiro_id = barbeiro.id
        ORDER BY cliente.id
    `)
    reply.send(clientes.rows)
})

// O SQL fica entre crases ( ` ) para poder quebrar em várias linhas.


// ### JOIN triplo: agendamento + barbeiro + cliente (critério 7.1)

O caderno pede: "listagem dos agendamentos ordenado por dia, trazendo TODOS os dados do barbeiro e do cliente".
Então juntamos as 3 tabelas e ordenamos pela data.

SELECT
    agendamento.id,
    agendamento.data_hora,
    barbeiro.id AS barbeiro_id,
    barbeiro.nome AS barbeiro_nome,
    cliente.id AS cliente_id,
    cliente.nome AS cliente_nome,
    cliente.cpf AS cliente_cpf
FROM agendamento
INNER JOIN barbeiro ON agendamento.barbeiro_id = barbeiro.id
INNER JOIN cliente ON agendamento.cliente_id = cliente.id
ORDER BY agendamento.data_hora ASC;

- ORDER BY coluna ASC = do menor para o maior (datas mais antigas primeiro).
- Para "todos os dados", liste as colunas que interessam de cada tabela, cada uma com seu apelido.
- O CPF e a senha do barbeiro ficam de fora porque estão em hash.

servidor.get('/agendamentos', { preHandler: autenticar }, async (request, reply) => {
    const agendamentos = await sql.query(`
        SELECT
            agendamento.id,
            agendamento.data_hora,
            barbeiro.id AS barbeiro_id,
            barbeiro.nome AS barbeiro_nome,
            cliente.id AS cliente_id,
            cliente.nome AS cliente_nome,
            cliente.cpf AS cliente_cpf
        FROM agendamento
        INNER JOIN barbeiro ON agendamento.barbeiro_id = barbeiro.id
        INNER JOIN cliente ON agendamento.cliente_id = cliente.id
        ORDER BY agendamento.data_hora ASC
    `)
    reply.send(agendamentos.rows)
})

// ### Erros comuns

- A busca sempre devolve tudo: o ? está faltando na URL ou o nome do parâmetro é diferente (request.query.busca x ?termo=).
- A busca não acha "ana" digitando "Ana": usou LIKE em vez de ILIKE.
- "column reference "id" is ambiguous": duas tabelas têm a coluna id. Escreva tabela.coluna (agendamento.id).
- Nome do cliente e do barbeiro aparecem iguais: faltou o AS (apelido) em um dos dois.
- "relation agendamento does not exist": o script saep_db.sql não foi rodado no banco certo (saep_db).
- A lista de agendamentos vem vazia: o INNER JOIN só traz registros que têm barbeiro E cliente válidos.
