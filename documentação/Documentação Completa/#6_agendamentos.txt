// ### Datas: como o sistema guarda e como o front envia

- No banco a coluna é TIMESTAMP (data e hora juntas): 2026-11-18 14:30:00.
- Front e API trocam datas no formato ISO: 2026-11-18T14:30 (o T separa a data da hora).
- O campo <input type="datetime-local"> já devolve exatamente esse formato no .value. Não precisa converter.
- Para MOSTRAR a data em português na tela: new Date(data).toLocaleString('pt-BR', ...)
  (a função formatarData do scripts.js faz isso).

// >>> server.js
servidor.post('/agendamentos', { preHandler: autenticar }, async (request, reply) => {
    const body = request.body

    if (!body || !body.data_agendamento || !body.servico || !body.barbeiro_id || !body.cliente_id) {
        return reply.status(400).send({ message: 'Data, serviço, barbeiro e cliente são obrigatórios!' })
    }

    await sql.query(
        'INSERT INTO agendamento (data_agendamento, servico, barbeiro_id, cliente_id) VALUES ($1, $2, $3, $4)',
        [body.data_agendamento, body.servico, body.barbeiro_id, body.cliente_id]
    )

    return reply.status(201).send({ message: 'Agendamento cadastrado!' })
})
// <<<

O PUT recebe SÓ a data nova e muda só essa coluna (critério 7.2):

// >>> server.js
// Atualiza SÓ a data do agendamento
servidor.put('/agendamentos/:id', { preHandler: autenticar }, async (request, reply) => {
    const body = request.body
    const id = request.params.id

    if (!body || !body.data_agendamento) {
        return reply.status(400).send({ message: 'A nova data é obrigatória!' })
    }

    const resultado = await sql.query(
        'UPDATE agendamento SET data_agendamento = $1 WHERE id = $2',
        [body.data_agendamento, id]
    )

    if (resultado.rowCount === 0) {
        return reply.status(404).send({ message: 'Agendamento não existe!' })
    }

    return reply.status(200).send({ message: 'Data do agendamento atualizada!' })
})
// <<<

// resultado.rowCount diz quantas linhas o UPDATE alterou. Se foi zero, o id não existe (404).
// Sempre use WHERE no UPDATE. Sem o WHERE, TODAS as linhas da tabela mudam de data.
// (Se ainda não fez a função autenticar, tire o { preHandler: autenticar } por enquanto.)

// ### Passo 3: listar os agendamentos (critério 7.1)

Cole DENTRO do <script>, abaixo do protegerPagina():

// >>> FRONT/agendamentos.html
        async function carregarAgendamentos() {
            const agendamentos = await api('/agendamentos')
            const lista = document.getElementById('lista')
            lista.innerHTML = ''

            agendamentos.forEach((ag) => {
                lista.innerHTML += `
                <div class="item">
                    <b>${formatarData(ag.data_agendamento)}</b> - ${ag.servico} <br>
                    barbeiro: ${ag.barbeiro_nome} - ${ag.barbeiro_email} - ${ag.barbeiro_telefone || ''} <br>
                    cliente: ${ag.cliente_nome} - ${ag.cliente_telefone || ''} - estilo: ${ag.cliente_estilo_corte || ''} <br>
                    <input type="datetime-local" id="data-${ag.id}">
                    <button onclick="atualizarData(${ag.id})">atualizar data</button>
                </div>`
            })
        }
// <<<

E a chamada, SEMPRE na última linha do script (acima do </script>):

// ### Passo 4: atualizar a data (critério 7.2)

Cole ACIMA da linha carregarAgendamentos() do final:

// >>> FRONT/agendamentos.html
        async function atualizarData(id) {
            const novaData = document.getElementById(`data-${id}`).value

            if (!novaData) {
                alert('Escolha a nova data!')
                return
            }

            const dados = await api(`/agendamentos/${id}`, 'PUT', { data_agendamento: novaData })
            alert(dados.message)
            carregarAgendamentos()
        }
// <<<

// - O botão atualizar data da linha chama atualizarData(${ag.id}), então a função recebe o id certo.
// - Lemos o campo da MESMA linha com getElementById(`data-${id}`).
// - O PUT leva só a data nova no body: { data_agendamento: novaData }.
// - Depois de atualizar, carregarAgendamentos() busca a lista de novo e ela já aparece na nova ordem.

// ### Erros comuns

- A data aparece "Invalid Date": o campo da API tem outro nome (confira o apelido no SELECT e no Network do F12).
- A lista não está ordenada: faltou o ORDER BY data_agendamento no GET /agendamentos.
- A data mudou de horário (algumas horas a mais ou a menos): o JavaScript converteu o fuso. Mande a data como veio do input
  (2026-11-17T08:30) e deixe o Postgres guardar como TIMESTAMP, sem timezone.
- Atualizou e nada mudou: o botão está lendo o campo errado. Confira se o id do input é data-${ag.id}.
- "Escolha a nova data!": o campo da linha está vazio, o usuário precisa preencher antes de clicar.
- "atualizarData is not defined": a função ainda não foi colada (passo 4), ou foi colada fora do <script>.
